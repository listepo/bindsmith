bindsmith

Как построить консольный генератор биндингов нативных API для шести платформ Flutter — Android, iOS, macOS, Windows, Linux и Web — и что для этого уже сделано в Dart, .NET, NativeScript и Rust-мире.

Метод: 8 исследовательских агентов → 5 фактчеков → синтез Опровергнуто утверждений: 17 Файлы проекта: ~/GitHub/bindsmith/research.md · plan.md
Вердикт

Писать на Dart, статический кодоген, оркестратор над официальными генераторами. Все кирпичи для отдельных платформ уже существуют и живы: ffigen 22 (C и Objective-C), swiftgen 0.2 (Swift), jnigen 1.0 (Java/Kotlin), package:win32 из Win32Metadata, dart-dbus, dart:js_interop. Не существует ни одного инструмента, который берёт одну декларацию и выдаёт биндинги для всех шести платформ плюс единый Dart-фасад — ближайшее, flutter_rust_bridge, умеет это только для Rust-входа.

Ниша bindsmith: один конфиг → драйверы над ffigen/swiftgen/jnigen/winmd/dbus и собственный драйвер .d.ts для Web → единое промежуточное представление → проходы (фильтры, переименования, nullability, async, потоки, фиксапы) → платформенные биндинги, фасад с диспатчем, тонкие нативные обёртки для того, что напрямую не биндится, и lockfile зависимостей. Динамический путь NativeScript отвергнут: свой рантайм, нет tree-shaking, ~3,5× накладных на вызов.

Постановка

Задача и рамки

Нужна программа, которая по описанию нативного API — заголовки C/Objective-C, Swift-модули, JAR/AAR, TypeScript-декларации, .winmd, .gir, D-Bus XML — генерирует Dart-биндинги для каждой платформы Flutter, запускается из командной строки и управляется конфигами. Ориентиры: Mono/Xamarin/.NET MAUI, NativeScript, а также uniffi, flutter_rust_bridge, Gluecodium.

Важно разделять два направления интеропа. Первое — native → Dart: Dart вызывает существующий нативный API напрямую (ffigen, swiftgen, jnigen, js_interop). Второе — Dart ↔ native через каналы: описываем интерфейс сообщений и генерируем обе стороны (pigeon). Задача — первое; pigeon остаётся запасным выходом там, где прямой вызов невозможен.

Кто чем пользуется

  • Плагины команды Flutter (webview_flutter, camera, video_player, in_app_purchase, local_auth) — pigeon; path_provider, url_launcher, shared_preferences — рукописные каналы.
  • Команда Dart: cupertino_http — ffigen ObjC; ok_http — jnigen; sqlite3 — ffigen C.
  • HERE SDK — Gluecodium с официальной Dart-целью. Sentry и Nutrient движутся к FFI/JNI-биндингам вместо каналов не перепроверено.
  • Ни один вендор не генерирует Flutter-обёртки из SDK автоматически.

Что болит у авторов плагинов

  • Web всегда отдельная реализация — pigeon его не покрывает.
  • jnigen требует собранный classpath: «сначала собери Android».
  • Swift-only SDK без @objc невидимы для ffigen; структуры и генерики Swift не пробрасываются.
  • Корутины, default-параметры, companion-объекты Kotlin требуют фасада.
  • Память и потоки: JNI global refs, main-thread API UIKit, коллбеки, которые собирает GC.
  • Разные конфиги у каждого инструмента; миграция YAML → Dart-скрипты в 2026.

Аналоги в других экосистемах

Что у них можно взять: не код, а решения.

Mono · Xamarin · .NET MAUI

Ручной IDL, генератор, фиксапы, slim binding

  • bgen (iOS/macOS): ApiDefinition.cs с [BaseType], [Export], [NullAllowed], [Wrap]; все Apple SDK привязаны так вручную. RFC на Roslyn-генератор открыт с 2024, работ нет.
  • Objective Sharpie: dotnet global tool Sharpie.Bind.Tool, только macOS, libclang. Атрибут [Verify] намеренно ломает компиляцию, пока разработчик не проверит место. Лучший UX принудительного ревью.
  • .NET for Android: class-parse (байткод + метаданные Kotlin) → api.xml → generator; фиксапы Metadata.xml на XPath (remove-node, attr, add-node); <AndroidMavenLibrary> в .NET 9 тянет Maven и верифицирует зависимости.
  • Native Library Interop: официальный совет — не биндить SDK целиком, а написать тонкую Swift/Kotlin-обёртку и биндить её (шаблон в CommunityToolkit/Maui.NativeLibraryInterop).
  • CsWin32: pull-модель — NativeMethods.txt перечисляет нужные API, source generator берёт их из .winmd. CppSharp 1.2, ClangSharp 21.1.8 — C/C++ через libclang с конвейером passes.
NativeScript

Динамический полюс

  • Метаданные всего SDK генерируются при сборке: iOS — C++/libclang генератор → бинарный metadata-<arch>.bin; Android — ASM/BCEL → tree-streams.
  • Рантайм (V8 на iOS с версии 7.0, 2020) диспатчит вызовы через libffi/objc_msgSend и JNI-рефлексию. Покрытие 100% без кодогена под библиотеку.
  • Фильтрация — native-api-usage.json (whitelist/blacklist); типы для IDE — ns typings ios|android; пакеты типов 15 и 48 МБ.
  • Цена: рантайм и метаданные в бинаре, нет tree-shaking, ≈3,5× накладных на вызов по собственному бенчмарку NativeScript. Для Flutter с AOT на iOS путь закрыт. Берём идею whitelist-использования API.
  • Родня: dart_native (Alibaba) — заброшен с декабря 2022; PyObjC, Pyjnius, JNA, koffi.
Rust и IDL

Единая модель и шаблоны

  • uniffi-rs 0.32: Rust → Kotlin/Swift/Python/Ruby; сторонние Go, C#, React Native и Dart (Uniffi-Dart 0.2.1, активен). ComponentInterface + Askama-шаблоны + checksum'ы совместимости.
  • flutter_rust_bridge 2.13: единственный зрелый «одна декларация → 6 платформ», но вход только Rust; flutter_rust_bridge.yaml, cargokit или native assets.
  • Gluecodium 14.1 (HERE): LIME IDL → C++, Java, Kotlin, Swift, Dart. Djinni мёртв (релиз 2023), SWIG и wit-bindgen без Dart.
  • objc2 header-translator: translation-config.toml на фреймворк — skipped, availability по ОС, safety-флаги. Образец декларативных фиксапов.
  • gtk-rs gir: Gir.toml, два слоя sys и safe. windows-bindgen 0.100: --filter как pull-модель из winmd.
Kotlin · Swift · Java · JS

Уроки маппинга

  • Kotlin cinterop .def; Swift export экспериментален; SKIE 0.10 чинит suspend/Flow на Swift-стороне; karakum — .d.ts → Kotlin через TypeScript Compiler API.
  • swift-java 0.6: режимы FFM (JDK 25+) и JNI (Android). jextract: dump-then-curate — --dump-includes, отредактировать, --config.
  • React Native codegen по TS-спекам; Nitro/nitrogen; Expo Modules DSL. Agora Terra: cppast + libclang → AST → TS-рендереры, YAML-конфиг.
  • Общее: async у каждого свой (suspend/Flow, Swift async, Promise → Future/Stream); nullability из аннотаций; генерики стираются; документация теряется почти у всех; snapshot-тесты и компиляционная матрица — стандарт.

Как это делается

Как генерируют interop нативного API на каждой платформе

Единая схема: вход → генератор и конфиг → команды → рантайм → сборка → подводные камни. Сниппеты схематичны: имена классов взяты из changelog'ов ffigen 22 и jnigen 1.0, точные сигнатуры — в API-docs пакетов.

Android

стабильноjnigen 1.0.0 · jni 1.0.3
Вход
.class, JAR/AAR (в том числе из Maven) или Java-исходники. Kotlin только скомпилированный; его метаданные дают nullability и suspend.
Конфиг
tool/jnigen.dart; YAML остался как legacy.
import 'package:jnigen/jnigen.dart';

void main() => JniGenerator(
      input: Input(
        classes: ['androidx.biometric.BiometricPrompt'],
        // maven-зависимости, android_sdk_config(add_gradle_deps), source_path…
      ),
      output: DartOutput(path: Uri.directory('lib/src/android/')),
    ).generate();
Команды
dart run tool/jnigen.dart. Для плагина с Android-примером jnigen сам вызывает Gradle, чтобы получить classpath.
Рантайм
package:jni: JObject, JString, JList/JMap, Jni.spawn() для десктопной JVM, интерфейсы реализуются из Dart через implement(), глобальные ссылки освобождаются .release().
Сборка
ffiPlugin: true, Gradle-зависимости, R8/ProGuard keep-правила для классов, вызываемых из Dart; JDK 17–21.
Камни
  • Нумерованные суффиксы перегрузок меняются между версиями генератора.
  • Корутины, default-параметры, companion-объекты требуют Kotlin-фасада.
  • Коллбек-объект нужно держать в Dart-ссылке, иначе его соберёт GC.

iOS и macOS

ObjC стабильноSwift экспериментальноffigen 22 · objective_c 9.6 · swiftgen 0.2
Вход
Objective-C: заголовки фреймворков (системных, из xcframework или pod). Swift: модуль; swiftgen сам делает swift2objc → swiftc -emit-objc-header → ffigen.
Конфиг
tool/ffigen.dart для ObjC, tool/swiftgen.dart с SwiftGenerator(target:, inputs:, include:, output:, ffigen:) для Swift.
import 'package:ffigen/ffigen.dart';

void main() => FfiGenerator(
      input: Input(entryPoints: [Uri.file('src/wrapper.h')] /*, objc, compilerOpts */),
      output: DartOutput(path: Uri.file('lib/src/ios/av.dart')),
      // include-фильтры интерфейсов/протоколов/категорий, visitor для переименований
    ).generate();
Команды
dart run tool/ffigen.dart, dart run tool/swiftgen.dart. Коммитить и .g.dart, и .m: последний должен попадать в Classes/** podspec'а.
Рантайм
package:objective_c: ARC через NativeFinalizer, блоки .fromFunction / .listener / .blocking, протоколы через $Builder.implementAsListener; package:ffi.
Сборка
podspec s.frameworks = 'AVFoundation' или SwiftPM linkerSettings: [.linkedFramework(...)]; ffiPlugin: true для ios и macos.
Камни
  • Видны только @objc/NSObject-совместимые Swift-API; структуры и генерики не пробрасываются.
  • Блоки с чужого потока — только .listener/.blocking; UIKit и AppKit — main thread.
  • Без include-фильтров ffigen тянет миллионы строк транзитивных фреймворков; макросы не переносятся.

Windows

стабильноffigen 22 · win32 6.4 · winmd 7.1 · native_toolchain_c
Вход
C-заголовки свои или из Windows SDK (Windows Kits\10\Include\…\um|shared). Для Win32/COM — .winmd из NuGet Microsoft.Windows.SDK.Win32Metadata.
Генератор
ffigen с compilerOpts: ['-I…']. Win32 — готовый package:win32, самим не регенерировать; для кастомного среза — package:winmd как читатель метаданных. C++ SDK — extern "C" шим, собираемый из hook/build.dart.
Рантайм
package:ffi, package:win32 (COM vtables, calloc/free).
Сборка
// hook/build.dart
import 'package:hooks/hooks.dart';
import 'package:native_toolchain_c/native_toolchain_c.dart';

void main(List<String> args) => build(args, (input, output) async {
      await CBuilder.library(
        name: 'sdk_shim', assetName: 'sdk_shim.dart', sources: ['src/shim.c'],
      ).run(input: input, output: output);
    });
Каналы — pigeon C++ (cppHeaderOut, cppSourceOut).
Камни
  • libclang нужен ffigen и на Windows.
  • SAL-аннотации и __stdcall; MSVC-редистрибутивы при дистрибуции.
  • pigeon C++ с багами forward-declaration (flutter/flutter#128330).

Linux

C и D-Bus стабильно.gir незрелыйffigen 22 · dbus 0.7.15 · gir-binding-gen
Вход
C-заголовки с include-путями из pkg-config --cflags gtk+-3.0; D-Bus introspection XML; .gir.
Генератор
ffigen (так Canonical делает glib.dart и stdlibc.dart); dart-dbus generate-remote-object iface.xml -o lib/x.dart для клиента, generate-object для сервера; gir-binding-gen от сообщества.
Рантайм
package:ffi, package:dbus.
Сборка
hook/build.dart + ffiPlugin: true; каналы — pigeon GObject. Embedder Flutter Linux — GTK3, миграция на GTK4 стоит с 2021.
Камни
  • Макросы G_OBJECT()-кастов и varargs g_object_new ffigen не переносит.
  • Версии glibc на целевых дистрибутивах.
  • Код dart-dbus черновой, требует доводки.

Web

js_interop стабильногенерации из .d.ts нетdart:js_interop · package:web
Вход
Браузерные API — WebIDL, уже сгенерированы в package:web. JS-библиотеки — .d.ts из npm или ручные декларации.
Генератор
Для приложений — ручные extension types. Автоматика из .d.ts — только неопубликованный js_interop_gen в dart-lang/web; js_facade_gen архивирован в 2022.
import 'dart:js_interop';

extension type Chart(JSObject _) implements JSObject {
  external Chart(JSObject context, JSObject options);
  external JSPromise<JSAny?> update();
  external void destroy();
}

Future<void> refresh(Chart c) => c.update().toDart;
Рантайм
dart:js_interop (JSPromise.toDart, .toJS, JSFunction), package:web.
Сборка
<script> в web/index.html или загрузка в flutter_bootstrap.js; плагин — pluginClass и fileName в блоке web.
Камни
  • Структурная типизация TS против номинальных extension types.
  • Коллбеки держать (.toJS), иначе GC.
  • dart:html и package:js не собираются dart2wasm.

Упаковка и каналы

стабильноpackage_ffi · federated plugin · pigeon 28
Шаблон
flutter create --template=package_ffi <name> (Flutter ≥ 3.38): lib/, src/, hook/build.dart; в dev_dependencies — hooks, code_assets, native_toolchain_c.
Federated
App-facing пакет с default_package: на платформу; реализации с implements:; для FFI-реализаций ffiPlugin: true.
Pigeon
dart run pigeon --input pigeons/messages.dart; @HostApi, @FlutterApi, @ProxyApi; @async → Kotlin suspend и Swift async throws. Одна версия pigeon на обеих сторонах; публичные API на pigeon не рекомендуются.

Что заимствуем и откуда

  • Pull-модель списков API — CsWin32 NativeMethods.txt, windows-bindgen --filter, NativeScript native-api-usage.json.
  • Dump-then-curate — jextract --dump-includes → bindsmith dump.
  • Декларативные фиксапы — objc2 translation-config.toml, Xamarin Metadata.xml, gtk-rs Gir.toml.
  • Маркеры ревью, ломающие сборку — Objective Sharpie [Verify].
  • Slim binding как артефакт — MAUI Native Library Interop, но генерируемый.
  • Разрешение зависимостей с верификацией — AndroidMavenLibrary; lockfile — cargo/pub.

Чего не делаем (YAGNI)

  • Свой рантайм или динамический диспатч.
  • Собственный парсер C++ — вместо него extern "C" шим и тонкая обёртка.
  • Поддержка макросов препроцессора.
  • GUI, обязательные AI-зависимости, собственный форматтер и анализатор.

03 дня

Скелет и решения

Pub workspace: пакеты bindsmith (CLI, драйверы, IR, проходы, эмиттеры) и bindsmith_runtime (аннотация verify, диспатч, ошибки). CI на трёх ОС. Пять ADR: язык, статика, формат конфига, драйверы над библиотеками, pull-модель. Пиннинг апстрима одной мажорной версией.

Готово, когда: CI зелёный на macOS, Ubuntu, Windows; bindsmith --help печатает команды.

11,5 недели

Конфиг, IR, первый срез — драйвер C

Типизированный конфиг с JSON Schema и понятными ошибками; модель IR; интерфейс драйвера; драйвер C над ffigen через FfiGenerator и visitor-API; эмиттер с hook/build.dart; команды init, doctor, generate, dump; golden-тесты на фикстуре.

Готово, когда: фикстура fixtures/c/geometry генерируется и компилируется на Ubuntu и macOS.

22 недели

Apple: Objective-C и Swift

ObjC-драйвер: completion handlers → Future, блоки с чужого потока → listener, фиксап threading. Swift-драйвер через SwiftGenerator с адаптером под нестабильный API; Swift-only члены фиксируются как dropped-маркеры. Эмиссия podspec и SwiftPM.

Готово, когда: фикстуры ObjC и Swift проходят dart test на macOS; podspec проходит lint.

32 недели

Android: jnigen, Maven, lockfile

Резолвер Maven с транзитивными POM и sha256 в lockfile; JVM-драйвер над JniGenerator; keep-правила R8, Gradle-сниппет; фикстура Kotlin с перегрузками, интерфейсом, suspend, Flow, default-параметрами; тесты через Jni.spawn на десктопной JVM.

Готово, когда: повторная генерация с lockfile работает офлайн; diff ловит перенумерацию перегрузок.

42 недели

Web: драйвер .d.ts

Сайдкар на TypeScript Compiler API выдаёт JSON деклараций; драйвер переводит его в IR; эмиттер выпускает extension types с @JS, JSPromise → Future в фасаде. Всё неподдерживаемое — маркер, никогда не молчаливый пропуск. Проверка dart2js и dart2wasm.

Готово, когда: фикстуры nanoid, uuid и подмножество chart.js компилируются в JS и Wasm.

51,5 недели

Windows и Linux

winmd-драйвер с pull-списком: если символ уже есть в package:win32, фасад реэкспортирует его, генерируются только пробелы. Linux: pkg-config для драйвера C, D-Bus-драйвер, маркеры для макросов GLib. Шаблоны hook/build.dart для C и CMake, шим для C++.

Готово, когда: фикстуры генерируются и анализируются на windows-latest и ubuntu-latest.

62 недели

Фасад, проходы, фиксапы, verify

Все проходы как чистые функции с unit-тестами; фасад с conditional imports и рантайм-диспатчем; аннотация verify блокирует bindsmith verify до снятия или подтверждения в конфиге; команды explain, diff, watch, generate --check.

Готово, когда: фикстура на шесть платформ даёт одну библиотеку с идентичным публичным API (проверка через analyzer).

72 недели

Генерация тонких обёрток

Из dropped-маркеров: Swift @objc-мост для структур, генериков и async; Kotlin-мост для Flow, default-параметров и sealed; C++ шим extern "C". Обёртки коммитятся и редактируются в размеченных регионах, затем прогоняются через обычные драйверы.

Готово, когда: Swift-only метод фикстуры вызывается из Dart; Flow становится Stream.

82 недели

Реальные примеры, документация, релиз

Пять примеров: AVFoundation, androidx.biometric, sqlite на десктопе, chart.js на Web, Swift-only пакет через обёртку. Документация из JSON Schema. Публикация на pub.dev, бинарники на GitHub Releases (кросс-компиляция dart compile exe — только в Linux, поэтому сборка на каждой ОС), Homebrew tap, pana ≥ 140.

Готово, когда: все примеры собираются в CI; пакеты опубликованы; сайт документации живой.

Чем bindsmith будет лучше существующего

  1. Одна декларация → шесть платформ и единый фасад. Сегодня это делает только flutter_rust_bridge, и только для Rust-входа.
  2. Паритет Web. .d.ts → dart:js_interop — публичного инструмента нет с 2022 года; issue про Web в pigeon открыт четыре года.
  3. Pull-модель, декларативные фиксапы и verify-маркеры — синтез CsWin32, objc2 и Sharpie; ни у одного Dart-инструмента этого нет.
  4. Slim binding как генерируемый артефакт, а не совет из документации.
  5. Зависимости и lockfile — генерация воспроизводима на CI без «сначала собери Android».
  6. Устойчивость к апстриму — пиннинг, адаптеры, контрактные тесты, diff после бампов.
  7. Перенос документации и availability в dartdoc и рантайм-проверки.
  8. Бюджет размера сгенерированного кода с отчётом, что можно исключить.
